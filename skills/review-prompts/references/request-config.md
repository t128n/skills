# Group 4: Request config and architecture

These surface beside prompt cruft; report them even though they are not prompt text. Mark the group `not applicable` in one line when the inventory lists no request-building or prompt-assembly code, except the sub-agent roster check, which applies to those agents' definition files.

- **API fossils.** Deprecated model IDs, parameters, and beta headers that error or are ignored on the target.
- **Thinking config and output ceilings sized for the wrong model.** Disabled-thinking flags or fixed thinking budgets on models that require adaptive or effort-based reasoning; output-token ceilings sized for non-thinking responses that truncate output because reasoning tokens count toward the completion budget.
- **History-editing harness.** Code that mutates the system prompt, the tool list, or earlier messages mid-session (deleting per-turn reminders, adding a tool mid-conversation instead of declaring it up front) breaks prompt-cache prefixes and invalidates preserved reasoning state. Propose append-only alternatives.
- **User text in the wrong place.** Mid-task user messages injected inside a tool-result block, as a mid-conversation system message right after a tool result, or as countdown text after tool results lead models to treat user input as untrusted tool output. Keep user input in genuine user turns after tool results.
- **Cache-hostile ordering.** Timestamps, request UUIDs, or per-user variables interpolated above static system instructions or tool schemas invalidate prefix caching on every request. Move dynamic context to the end of the system block or into the user turn.
- **Budget countdowns rendered into context.** Remaining-token or remaining-step counts shown to the model cause premature wrap-up and corner-cutting. Keep budget enforcement in the harness.
- **An LLM executor for a deterministic plan.** In every pipeline, batch job, or agent loop, *count the model-call sites* and ask of each whether its inputs fully determine its output; transcripts repeating the same deterministic loop N times are the tell. Routing, tallying, normalizing, filtering, and formatting belong in plain code; keep a model call only where the work is adaptive (classifying ambiguous cases, synthesizing judgment). Zero model calls is an over-fix when a judgment step exists: name the call that stays.
- **Redundant specialist sub-agents.** Inspect the sub-agent roster as a surface of its own. Two sub-agents with the same task, the same tools, and near-duplicate prompts, differing only in a filter or payload parameter, consolidate into one parameterized agent. Propose a concrete roster diff deleting the redundant definition and folding its parameter into the survivor.
- **No token accounting.** Without per-surface token and cost visibility, prompt bloat and cache misses are invisible. If the codebase lacks it, recommend adding it first, as the prerequisite for measuring cleanup.
