# Technical writing

- Write for the reader's task and familiarity with the subject. Lead with the purpose or outcome, then provide only the context needed to understand and act.
- Describe observable behavior, interfaces, prerequisites, constraints, and failure modes where relevant. Explain non-obvious rationale when supported by evidence; do not invent historical reasons.
- Separate verified facts from assumptions, incomplete findings, future plans, and recommendations. Preserve existing document status and identify uncertainty rather than filling gaps with plausible details.
- Use precise terms, short sections, descriptive headings, and consistent names. Avoid repeating code line by line or restating facts that are easier to discover from the implementation.
- Make examples representative and safe: include necessary context and placeholders, avoid real secrets, and verify commands or examples when practical. Identify anything untested and avoid implying that it was executed.
- Link to authoritative sources instead of duplicating volatile details. Use project terminology and style, and avoid introducing rules that conflict with the project's writing conventions.
