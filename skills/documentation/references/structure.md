# Documentation structure

- Start with the project's existing entry points, document locations, naming, and ownership conventions. Preserve existing information architecture unless the user asks to change it.
- Place information where its intended audience will look for it. An entry-point README can explain purpose, prerequisites, setup, and navigation; supporting documents can hold details that would obscure that entry point.
- Keep a single authoritative explanation for each subject and link to it from related material. Prefer targeted additions to existing documents over parallel summaries that can diverge.
- If no convention exists, a README at the relevant project entry point and supporting Markdown under `docs/` are reasonable defaults, not required directories. Choose a simpler location when appropriate.
- Link to relevant source, decisions, and operational guidance when that helps navigation. Preserve existing link conventions and check relative paths from the document containing them.
- Do not introduce a documentation system, generator, or mandatory document structure without a demonstrated need and appropriate authorization.
